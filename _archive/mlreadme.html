Machine Learning in Stock Trading App

An Engineering Explanation of ML Components & Implementation

1. System Architecture Overview

The machine learning subsystem of the Stock Trading App is designed with a clean separation of concerns, following a modular architecture that enables both technical analysis and ML-based predictions to work independently or in a hybrid fashion.

┌─────────────────┐     ┌─────────────────┐     ┌─────────────────┐
│   Data Fetcher  │────▶│ Feature Engineer │────▶│   ML Training   │
└─────────────────┘     └─────────────────┘     └─────────────────┘
         │                      │                        │
         │                      │                        │
         ▼                      ▼                        ▼
┌─────────────────┐     ┌─────────────────┐     ┌─────────────────┐
│  Data Storage   │◀───▶│  ML Prediction  │◀───▶│ Model Manager   │
└─────────────────┘     └─────────────────┘     └─────────────────┘
         │                      │                        │
         │                      │                        │
         ▼                      ▼                        ▼
┌─────────────────┐     ┌─────────────────┐     ┌─────────────────┐
│ TA Calculation  │────▶│ Hybrid Decision │◀────│Feature Importance│
└─────────────────┘     └─────────────────┘     └─────────────────┘

The system consists of three main components:

  1. Feature Engineering: Transforms raw market data into ML-ready features
  2. Model Management: Trains, saves, loads and manages prediction models
  3. Prediction Service: Coordinates feature preparation, prediction, and hybrid decision making

2. Feature Engineering

The FeatureEngineer class is responsible for transforming raw OHLCV (Open, High, Low, Close, Volume) stock data into features suitable for machine learning models. This is a critical step that directly impacts model performance.

Key Feature Categories:

  • Price Features: Basic transformations of price data (returns, logarithmic returns, price ranges)
  • Technical Indicators: Standard indicators like SMAs, EMAs, Bollinger Bands, RSI, MACD
  • Date Features: Calendar-based features (day of week/month, month, quarter, year)
  • Target Variables: Future returns calculated for specified prediction horizons

Implementation Detail: The feature engineering process is intentionally built without TA-Lib dependency, instead implementing indicators using pandas operations. This design choice enhances portability and simplifies deployment requirements.

Feature Generation Process:

// Simplified flow:
Raw OHLCV Data → Price Features → Technical Indicators → Date Features → Target Variables → ML-Ready Dataset

Each step adds new columns to the dataset, culminating in a feature-rich matrix that captures different aspects of market behavior. Importantly, the target variable generation includes a configurable threshold parameter that determines the significance level for classifying price moves.

Notable Implementation Details:

  • Forward-fill (ffill) is used to handle NaN values created during feature calculation
  • The highest quality features come from combining multiple time frames (5, 10, 20, 50, 200 periods)
  • Relative positions (e.g., current price relative to SMA) often provide stronger signals than absolute values
  • Future returns are calculated using shift(-horizon) to look forward in time
  • A 3-class target is created: 1 (up), 0 (neutral), -1 (down)

3. Model Management

The ModelManager class handles the lifecycle of ML models: training, evaluation, persistence, and loading. It provides a consistent interface regardless of the underlying model type.

Supported Classification Models:

Model Type Implementation Key Parameters
Random Forest RandomForestClassifier n_estimators=100, class_weight='balanced'
Gradient Boosting GradientBoostingClassifier random_state=42
Logistic Regression LogisticRegression max_iter=1000, class_weight='balanced'

Design Note: The class balancing in Random Forest and Logistic Regression is crucial for stock market prediction, where the distribution of up/down movements is often imbalanced, especially when using significance thresholds.

Feature Scaling and Model Pipeline:

All features are standardized using StandardScaler, which is critical for models like Logistic Regression. The scaler is persisted alongside the model to ensure consistent transformation during prediction.

def train_classification_model(self, X_train, y_train, model_type, feature_cols):
    # Fit the scaler ONLY on the training data
    X_train_scaled = self.scaler.fit_transform(X_train)

    # Create a new instance for each training run
    model = self.CLASSIFICATION_MODELS[model_type]

    # Train the model
    model.fit(X_train_scaled, y_train)

    # Store model and feature information
    self.current_model = model
    self.current_model_type = 'classification'
    self.feature_columns = feature_cols

The manager also handles feature importance extraction, which varies by model type:

  • Tree-based models (Random Forest, Gradient Boosting): Direct access via feature_importances_
  • Linear models (Logistic Regression): Use coefficient magnitudes via coef_

Model Persistence:

Models are saved using joblib with a structured naming convention:

{symbol}_{model_class_name}_{model_type}_{horizon}d_{timestamp}{suffix}.joblib

Each saved model includes:

  • The trained model object
  • The fitted scaler
  • Feature column names
  • Metadata (model type, symbol, horizon, timestamp)

4. ML Prediction Service

The MlPredictionService class acts as the orchestrator, coordinating data preparation, model loading, prediction, and hybrid recommendations. It provides a high-level API for the UI to interact with.

Key Capabilities:

  • Model Training: Orchestrates the complete training pipeline
  • Model Loading: Loads the latest model for a specific symbol and horizon
  • Prediction: Generates predictions using loaded models
  • Hybrid Recommendations: Combines ML predictions with technical analysis
  • Feature Importance: Provides feature importance visualization data

Prediction Confidence Levels:

The service translates raw prediction probabilities into confidence levels:

Confidence Level Probability Threshold
STRONG ≥ 0.80
MODERATE ≥ 0.65
WEAK ≥ 0.55
UNCERTAIN < 0.55

Hybrid Decision Making:

One of the most sophisticated aspects is the hybrid recommendation system that combines ML predictions with traditional technical analysis:

def get_hybrid_recommendation(self, df, technical_score, adx_value, target_threshold):
    # Get ML prediction
    ml_prediction = self.predict(df, target_threshold=target_threshold)

    # Calculate ML signal and weight
    ml_signal = ml_prediction.get('prediction', 0)
    ml_score = ml_signal * 3.0  # Scale ML signal

    # Weight based on confidence
    confidence_level = ml_prediction.get('confidence_level', 'UNCERTAIN')
    if confidence_level == 'STRONG': ml_weight = 0.70
    elif confidence_level == 'MODERATE': ml_weight = 0.60
    elif confidence_level == 'WEAK': ml_weight = 0.50
    else: ml_weight = 0.40  # UNCERTAIN or N/A

    # Adjust by trend strength (ADX)
    trend_adjustment = 1.0
    if adx_value is not None:
        if adx_value > 30: trend_adjustment = 1.15; trend_strength = "STRONG"
        elif adx_value > 20: trend_adjustment = 1.05; trend_strength = "MODERATE"
        else: trend_adjustment = 0.90; trend_strength = "WEAK"
        ml_weight *= trend_adjustment
        ml_weight = max(0.3, min(0.8, ml_weight))  # Cap weight

    # Calculate technical weight and hybrid score
    tech_weight = 1.0 - ml_weight
    hybrid_score = (ml_score * ml_weight) + (technical_score * tech_weight)

    # Generate recommendation
    if hybrid_score >= 2.0: hybrid_recommendation = "BUY"
    elif hybrid_score >= 0.5: hybrid_recommendation = "WEAK BUY"
    elif hybrid_score <= -2.0: hybrid_recommendation = "SELL"
    elif hybrid_score <= -0.5: hybrid_recommendation = "WEAK SELL"
    else: hybrid_recommendation = "HOLD"

Engineering Insight: This carefully calibrated hybrid approach addresses the limitations of both pure ML (which can overfit or fail to account for macro factors) and pure technical analysis (which may miss subtle patterns). The system dynamically adjusts the weight given to ML predictions based on confidence and trend strength.

5. UI Integration

The ML components are deeply integrated with the application's UI via the App class, providing an intuitive interface for users to train models, view predictions, and understand feature importance.

Key UI Elements:

  • ML Training Controls: Model type selection, horizon, threshold, and test split parameters
  • ML LED: Visual indicator of ML processing and model loading status
  • Feature Importance Visualization: Bar chart displaying the most influential features
  • Matrix Display: Shows hybrid recommendations with color coding

The application intelligently manages UI state during ML operations, ensuring a responsive experience even during intensive operations like model training.

6. Parameter Tuning & Optimization

Critical ML Parameters:

Parameter Description Impact
prediction_horizon Number of days to look ahead for target calculation (default: 5) Longer horizons generally result in more stable predictions but lower accuracy
target_threshold Significance level for classifying price movements (default: 0.01 = 1%) Higher thresholds create clearer signals but fewer trading opportunities
test_size Proportion of data used for testing (default: 0.2 = 20%) Affects evaluation reliability and amount of training data
model_type Classification algorithm to use (default: random_forest) Different models have varying strengths with different market conditions

Optimization Insight: The system is designed to maintain a clear separation between training and testing data to prevent lookahead bias. This is critical in financial applications where chronological order matters and random shuffling would create false signals.

7. Memory & Performance Considerations

The ML subsystem is engineered with several optimizations for memory usage and performance:

Memory Management:

  • Models are loaded only when needed, rather than keeping all models in memory
  • Feature calculation is performed on-demand rather than precomputing all features
  • Raw data and feature matrices are copied when needed to prevent accidental modification

Performance Optimizations:

  • Vectorized operations using pandas and numpy for feature calculation
  • Efficient storage of models using joblib serialization
  • Background loading of ML models to prevent UI freezing
  • Parallel computation avoided to ensure compatibility with single-threaded environments

8. System Limitations & Future Enhancements

Current Limitations:

  • Classification models only; regression for price prediction not implemented
  • Limited to daily data; intraday predictions not supported
  • No cross-asset or cross-market correlations exploited
  • Feature engineering is static; no automatic feature selection

Potential Enhancements:

  • Implement regression models for price target prediction
  • Add automatic hyperparameter tuning using grid search
  • Incorporate sentiment analysis from news/social media
  • Implement ensemble methods combining multiple model types
  • Add support for intraday prediction with appropriate features
  • Create rolling window validation for more robust evaluation
