1. System Overview

The Market Sentiment Analysis system integrates artificial intelligence capabilities from OpenAI's Assistants API with the Stock Trading App to provide nuanced sentiment analysis of financial assets. The system combines technical indicators, price data, and machine learning predictions to generate comprehensive market insights with actionable trading recommendations.

2. Assistant Training & Configuration

The core of the sentiment analysis system is a specialized OpenAI Assistant that has been configured for financial market analysis. This section details how the assistant is created, configured, and optimized for stock market sentiment analysis.

2.1 Assistant Creation Process

The assistant is created programmatically using the OpenAI Assistants API. The system first checks if a previously created assistant exists and reuses it if found. If no assistant is found, a new one is created with specific parameters:

# Creating a new assistant assistant = client.beta.assistants.create( name="Stock Market Sentiment Analyzer", description="Analyzes stock market data and provides sentiment analysis with actionable insights", model="gpt-4-turbo-preview", tools=[{"type": "code_interpreter"}], instructions="[Detailed instructions here]" )

2.2 Assistant Configuration Parameters

Parameter Value Description
name Stock Market Sentiment Analyzer Identifier for the assistant
model gpt-4-turbo-preview The most advanced model for financial analysis
tools code_interpreter Enables data analysis capabilities

2.3 Assistant Instruction Engineering

The most critical aspect of the assistant's performance is the instruction set that trains it for market sentiment analysis. These instructions define the assistant's behavior, output format, and analytical approach.

Key Insight: Rather than fine-tuning a model (which would require significant data and resources), we use prompt engineering via the instructions parameter to create a specialized financial analyst assistant.

Instruction Structure

The instructions are structured in multiple sections:

  1. Role Definition: Establishes the assistant as a market sentiment analyzer
  2. Analytical Framework: Details the specific aspects of market data to analyze
  3. Response Format: Specifies the exact JSON structure for consistent parsing
  4. Guidelines: Provides rules for handling uncertainty and maintaining objectivity

Core Instruction Components

You are a Stock Market Sentiment Analyzer specializing in providing nuanced sentiment analysis
and actionable insights based on technical indicators, price data, and machine learning predictions.

When analyzing data:
1. Examine all technical indicators (RSI, MACD, moving averages, etc.) and highlight key signals
2. Analyze the recent price action and volume patterns
3. Consider the ML prediction probability and confidence levels
4. Provide an overall sentiment: POSITIVE, NEUTRAL, or NEGATIVE
5. Summarize 3-5 key factors that support your sentiment conclusion
6. Suggest potential trade considerations based on the horizon period
7. Note any significant risks or contrary indicators that traders should be aware of

Response Format Specification

A critical aspect of the instructions is the detailed JSON structure specification that ensures consistent, parseable output:

{ "symbol": "TICKER", "sentiment": "POSITIVE/NEUTRAL/NEGATIVE", "confidence": "HIGH/MEDIUM/LOW", "horizon_days": 5, "analysis_date": "YYYY-MM-DD", "key_indicators": [ {"indicator": "RSI", "value": 68.5, "interpretation": "Approaching overbought but still bullish"}, {"indicator": "MACD", "value": "Positive and rising", "interpretation": "Strong upward momentum"} ], "price_action": { "trend": "UPTREND/DOWNTREND/SIDEWAYS", "key_levels": { "support": [150.25, 148.60], "resistance": [155.30, 158.75] }, "pattern": "Breaking out of consolidation" }, "ml_prediction": { "direction": "UP/DOWN/NEUTRAL", "probability": 0.75, "interpretation": "Moderately confident bullish signal" }, "summary": "Brief overall assessment of the stock's outlook", "key_factors": [ "Factor 1 with explanation", "Factor 2 with explanation", "Factor 3 with explanation" ], "risks": [ "Risk 1 with explanation", "Risk 2 with explanation" ], "trade_considerations": "Specific considerations for traders based on the data" }

3. Data Processing & Communication Flow

3.1 Thread Management

The Assistants API uses a thread-based conversational model. For each sentiment analysis, the system:

  1. Creates a new conversation thread
  2. Adds a message containing preprocessed market data
  3. Initiates a run with the assistant
  4. Polls for run completion
  5. Retrieves and processes the response

3.2 Data Preparation

Before sending data to the assistant, the system transforms raw market data into a structured format that maximizes the assistant's analytical capabilities:

Preprocessing Steps:

  1. Data Selection: Filter to the most relevant time periods (e.g., last 30 days of price action)
  2. Technical Indicator Transformation: Format indicators with proper names and values
  3. ML Prediction Integration: Structure ML outputs for assistant consumption
  4. Message Formatting: Create a comprehensive prompt with clearly delineated data sections
# Example of data preparation message message = f""" Please analyze the following stock market data for {symbol} with a prediction horizon of {horizon_days} days. Recent Price Data (last 30 days): ```json {price_data_json} ``` Technical Indicators: ```json {json.dumps(technical_data, indent=2)} ``` Machine Learning Prediction: ```json {json.dumps(ml_prediction, indent=2)} ``` Based on this data, provide a comprehensive sentiment analysis with your assessment of whether the sentiment is POSITIVE, NEUTRAL, or NEGATIVE. Include key supporting indicators, potential risks, and trading considerations for a {horizon_days}-day horizon. Format your response as a detailed JSON structure as described in your instructions. """

3.3 JSON Parsing & Validation

After receiving the assistant's response, the system must extract and parse the JSON data:

# JSON extraction from assistant response try: # Try to parse the entire response as JSON first sentiment_data = json.loads(response_text) except json.JSONDecodeError: # If that fails, look for JSON inside code blocks import re json_match = re.search(r'```json\s*(.*?)\s*```', response_text, re.DOTALL) if json_match: json_text = json_match.group(1) sentiment_data = json.loads(json_text) else: # Last attempt - look for any text that looks like JSON json_match = re.search(r'({.*})', response_text, re.DOTALL) if json_match: json_text = json_match.group(1) sentiment_data = json.loads(json_text) else: raise Exception("Could not extract JSON from response")

Engineering Note: The system implements robust error handling and multiple fallback mechanisms for JSON extraction, as Assistant responses may sometimes wrap JSON in code blocks or include additional commentary.

4. HTML Report Generation

4.1 Report Design Philosophy

The HTML report is designed to be both informative and visually consistent with the application's retro-futuristic theme. Key design principles include:

  • Visual Hierarchy: Most important information (sentiment, confidence) is immediately visible
  • Thematic Consistency: Colors, fonts, and styling match the main application
  • Interactive Elements: LED animations and glowing effects create a dynamic experience
  • Responsive Layout: Report adapts to different screen sizes

4.2 Dynamic Color Coding

The report uses sentiment-based color coding to provide immediate visual feedback:

Sentiment Color Hex Code
POSITIVE Neon Green #39ff14
NEUTRAL Light Cyan #e0fbfc
NEGATIVE Neon Red/Pink #ff4d6d
ERROR Pink #ff69b4

4.3 Technical Implementation

The report generation process converts the JSON sentiment data into a formatted HTML document:

  1. HTML Template: Core structure with placeholders for dynamic content
  2. Dynamic Styling: CSS variables adjust based on sentiment
  3. Content Formatting: JSON fields are converted to appropriate HTML elements
  4. Temporary File Creation: HTML is saved to a temporary file
  5. Browser Display: System browser opens the HTML file

Implementation Detail: The system uses temporary files with unique names to allow multiple reports to be opened simultaneously without conflicts. These files are automatically cleaned up by the operating system's temporary file management.

5. UI Integration

5.1 Tab-Based Integration

The sentiment analysis module is integrated into the main application using a tab-based approach for minimal disruption to the existing UI:

  1. Creates a new tab "Sentiment" alongside existing "Parameters" and "ML" tabs
  2. Dynamically relocates existing UI elements to their respective tabs
  3. Initializes sentiment controls in the new tab

5.2 Interaction with Existing Components

The sentiment module interacts with several existing application components:

  • Data Fetcher: Accesses current stock data
  • ML Prediction Service: Retrieves current ML predictions
  • Technical Analysis: Uses calculated technical indicators
  • LED System: Indicates processing state using existing LED components
  • Logging System: Reports status and results to the console

5.3 API Key Management

The system provides multiple options for OpenAI API key management:

  1. Environment Variables: OPENAI_API_KEY can be set at system level
  2. Configuration File: API key can be stored in config.py
  3. UI Entry: Key can be entered directly in the application UI

For security, the key is masked when displayed in the UI, and the system validates the key before enabling the sentiment analysis functionality.

6. Performance Considerations

6.1 Latency Management

AI-based sentiment analysis introduces latency challenges that are handled through:

  • Asynchronous Processing: UI remains responsive during analysis
  • Status Indicators: Clear feedback on processing state
  • Efficient Data Preparation: Only relevant data is sent to the API

6.2 API Cost Optimization

The system implements several strategies to minimize API costs:

  • Assistant Reuse: The same assistant is reused across sessions
  • Data Selection: Only essential data is included in requests
  • Thread Management: New threads are created for each analysis to prevent context accumulation

6.3 Error Resilience

The system includes comprehensive error handling:

  • API Connection Issues: Graceful handling of network problems
  • Response Parsing Failures: Multiple fallback mechanisms for extracting JSON
  • UI State Management: Consistent UI state even after errors

Operational Note: Typical analysis time ranges from 5-15 seconds depending on data complexity and OpenAI API load. This is communicated to users via status indicators and LED animations.
